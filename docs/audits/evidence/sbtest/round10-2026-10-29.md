## 3. 交接 N = 0（PR #5）

场景：账号与种子都已完成、只补文件的续跑，没有 `--rotate-passwords` / `--confirm-rotate`。以前执行器会留下一个 0 行的 0600 交接文件，运行记录写「N = 0 条 … 0 条全部存进 vault 才覆盖删除文件」，读起来像还要存 vault。
修法：新增 `finishHandoff`（`scripts/sbtest/init-executor.mjs`），N 只取本次实际写入行数（`handoff.count()`）：

- N > 0：文件保留，记录与以前一致（N 条全部存进 vault 才覆盖删除）。
- N = 0：核对文件仍是 0 字节普通文件后删除；运行记录与输出写「N = 0 …不需要任何 save_login / vault 保存，不得为凑数改密；空交接文件 … 已核对为 0 字节并删除」。
- N = 0 但文件非空：不删，保留并要求人工核对。
- 写之前被拒绝（catch 路径）也走同一结论。

`tests/unit/sbtest-init-r10.test.ts`（5 个用例）：修复前 4 失败 / 1 通过（通过的是 execute 层「不建号、不改密、交接 0 行」——这是已有行为，用来固定前提）；修复后 5/5。
新 CLI 用例经 `main` 读钉住的迁移（与「CLI --resume（部分账号）」同一路径，起 git 子进程，次数未单独探针统计），给 `SPAWN_TIMEOUT`：单实例、非空闲 2441 ms（load1 5.55）、1460 ms（load1 6.46）；批量 2864 ms。
