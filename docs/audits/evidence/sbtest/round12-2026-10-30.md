## 1. 修了什么（PR #5，`scripts/sbtest/init-executor.mjs`）

### A. 执行状态与证据一致（createUsers / rotateAdopted 执行层）

- 新增 `Redirected extends Refused`（客户端收到 3xx 时抛出，仍从不跟随）。读请求和写之前的闸门收到 3xx 照旧按拒绝处理（退出码 2）。
- `createUsers`（`POST /auth/v1/admin/users`）/ `rotateAdopted`（`PUT /auth/v1/admin/users/{id}`）：请求**已经发出**后
  - 收到 3xx（`Redirected`）→ 结果未知（`unknown` / `password-unknown`），退出码 3；
  - 收到 5xx 或其他非 2xx、非 4xx 的状态 → 结果未知，退出码 3（修复前是失败，退出码 1）；
  - 超时 / 连接断开 / 响应丢失 → 结果未知，退出码 3（修复前已经如此）；
  - 4xx（例如 422、403）→ 显式拒绝，失败，退出码 1（不变）；401 → 凭据拒绝，退出码 2（不变）。
- 结果未知时立即停止后续一切写（不建下一个、不改下一个、不传文件），已确认 + 未知状态写进逐项结果与清点，不自动重试、不隐式改密。
- 交接写入：`writeSync` 短写也按写入失败处理（`ESHORTWRITE`），不计入 N。

### B. 运行记录（审计记录）写入失败

- 新增 `fallbackReceipt(...)`：运行记录写不出时，stderr 输出一行以 `{"receipt":"sbtest-run-fallback/v1"` 开头的 JSON，只取白名单字段
  `command / exit / run_id / attempt_id / phase / results / confirmed_writes / unknown_writes / inventory / record_write_failure`；
  逐项结果只取 file、outcome、verify、error（自由文本截断并去掉像凭据的片段与已知令牌值），写请求只取阶段、方法、打码路径（uuid 打码）、状态。
  密码、令牌、请求头、完整原始响应、交接文件内容一律不取。
- execute（包括写之前被拒绝）与 preflight 都走同一兜底：原退出码 1 / 2 / 3 原样保留；原成功 + 记录写入失败 → 4。
  修复前 preflight 的记录写入失败会把结论覆盖成 1（预检通过 → 1，预检拒绝 → 1）。
- 运行记录：「任何写端点本次一律未调用」改为只说**只读预检阶段（P0 / P1 / PS）**，并按请求记录核对次数；execute 记录新增「写端点调用（按本次请求记录）」一节（已确认 / 被拒 / 结果未知）。
- 措辞：N = 本次成功写入交接文件的记录条数（不是云端建号 / 改密次数）；交接写入失败时交接文件可能已部分写入（可能含密码片段），按敏感文件处理；不再写「密码不在任何地方 / 不在交接文件里」。
- 文档：ops/SBTEST-INIT.md §2（重定向例外）、§10.1（执行状态表、兜底回执、退出码 4 措辞、N 定义、敏感文件）、§11。
