### 2. 「Auth Admin 200 + users 数组」的证明力

执行器的项目服务准入要求 `GET /auth/v1/admin/users?per_page=1` → 200 且 `{users:[…]}`。这是**必要不充分**：

- 它证明线路上到达的凭据**此刻**被 GoTrue 当作 service_role 接受；
- 它**不证明来源**（是哪条 vault 条目、哪个服务注入的）；
- 它**不证明只限单个项目**（同一密钥 / 服务是否还绑到别的主机，看不到）；
- 它不证明注入稳定（别人新建 / 删除服务后行为会变）。
  范围与来源只能以站长在 Settings 里看到的绑定记录 / Hark 支持的答复为准。

### 2. 可见位置与核对方法

1. 工具返回值：`save_login` 返回 secret id（只记 id 前 8 位）。
2. Hark 内核对（只读）：`list_secrets type=login` → 找到该 id，记录它的 **scope**：
   - 若是完整主机 `azsou-site-git-candidate-…-azsous-projects.vercel.app` → 规范化尊重公共后缀（PSL），以后真实交接用这个 site 是安全的；
   - 若是 `vercel.app` → 说明按「最后两段」规范化：这条登录会对**所有** `*.vercel.app` 站点生效，**真实交接不能用 Preview 域名**，需要改方案（见 §3 备选）。
3. 站长核对（只看）：Hark → 头像 → **Settings → Connected Accounts**：应出现 1 条，账号 `fake-demo-not-a-user@example.invalid`，昵称带 `FAKE-DEMO`。截图时遮住除用户名外的内容。
4. 浏览器侧（可选，需另行批准，且只读）：打开该 Preview 的 `/login/`，确认浏览器代理能用该 secret id 填表——**不提交**（提交会对 azsou-test 发一次失败的登录请求；即便无害也不在本申请范围内）。

### 3. site 应该写哪个域名（分析与建议）

- 站点前端在**自己的** `/login/` 页面收集邮箱 / 密码，再用 anon key 调 `https://ovvfwkmqlejcpatmfqcd.supabase.co/auth/v1/token`。用户（和浏览器代理）**从不在 `*.supabase.co` 上输入密码**。
- `save_login` 的说明是「浏览器按 secret id 用 fill_secret 填写」，所以填表本身不依赖域名匹配；site 决定的是：条目挂在哪个站点下显示、以后访问该站点时是否自动登录。
- 因此 **vault 的 site 应是 Preview 登录页的主机**（站长 / 代理实际输入密码的域名），不是 `ovvfwkmqlejcpatmfqcd.supabase.co`。第八轮演示与 §10.1 原文写的是项目主机，第九轮已改为推荐 Preview 域名。
- 风险与备选：
  - 已观测到登录 scope 会被规范成可注册域名（`app.backboard.io` → `backboard.io` 等）。`vercel.app` 在 PSL 私有段；平台是否尊重 PSL **未知**——这正是本演示要回答的。
  - 若规范成 `vercel.app`：备选是给候选 Preview 配一个站长自有的子域名（例如 `test.azsou.com`）。但那会规范成 `azsou.com`，与生产登录共用站点 → 需用 nickname 区分；或干脆不按站点自动登录，只按 secret id 填写。由站长决定。
  - Vercel Preview 若开着 Deployment Protection，打开 `/login/` 之前还有一层 Vercel 登录——与本条无关，另记。

### 4. 删除方法（演示的最后一步，必做）

- `remove_secret secret_id=<上一步返回的 id>`（只删这一条；不会删 azsou-test 里的任何账号，那里本来就没有这个账号）。
- 删除后核对：`list_secrets type=login` 不再有该 id；站长在 Settings → Connected Accounts 里看不到它。
- 若删除失败或仍可见：停下，报告 id 前缀，交站长在 Settings 里手动删除。
