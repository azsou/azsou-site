# 默认不启用的运维工作流（站长第三轮 2026-10-28：另行启用）

这个目录里的文件 **GitHub 不会运行**（只有 `.github/workflows/` 里的文件才会被运行）。
每一个都要站长单独批准，再用一个单独的 PR 复制到 `.github/workflows/` 才生效；运维 PR #8 不包含它们。

| 文件                  | 作用                                                                                                 | 启用前站长要做的事                                                                                                        |
| --------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `db-backup-daily.yml` | 每天北京时间 03:30 定时运行与 `db-backup.yml` 相同的受保护备份（统一快照 + Storage 文件 + 强制加密） | 批准频率与 Actions 存储用量；在环境 `backup-production` 里加变量 `BACKUP_PROJECT_REF`；决定定时运行是否也等审批（默认等） |
| `backup-monitor.yml`  | 每 6 小时检查每日备份的最新加密产物，过期 / 缺失就开 `backup-alert` issue                            | 与每日备份一起启用（单独启用手动备份时它必然告警）；阈值仓库变量 `BACKUP_MAX_AGE_HOURS`，默认 26                          |
| `backup-offsite.yml`  | 把某次备份的 `.gpg` 原样复制到站长自己的 S3 兼容存储（异地第二份），不解密                           | 选定外部存储；创建环境 `backup-offsite` 并配置 `OFFSITE_*` Secret / 变量；设定外部存储的保留期                            |

`tests/ops/test_workflows.py` 断言：`.github/workflows/` 里的备份工作流没有任何定时触发、在受保护环境里运行；本目录的文件不在 `.github/workflows/`。
